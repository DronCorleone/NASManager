# NAS Manager 1.5.0

Релиз исправляет отображение иконок приложений, добавляет каталоговый fallback для отсутствующих изображений и выводит логи контейнеров сразу после секции «Нагрузка».

## Изменения

- Исправлено наложение загруженной картинки на буквенный placeholder: после успешной загрузки отображается только одна иконка.
- Расширена совместимость с иконками TrueNAS Apps. Сначала проверяются доступные метаданные установленного приложения, затем совместимые вложенные поля `source`, после чего best-effort используется документированный `catalog.apps.icon_url`.
- Каталоговые SVG отображаются локальным dependency-free renderer; для загрузки иконок не передаются учётные данные TrueNAS.
- Если приложение не публикует валидную иконку либо загрузка не удалась, остаётся аккуратный placeholder с первой буквой названия.
- В подробной карточке после «Нагрузка» добавлена секция «Логи» с выбором контейнера, последними 200 строками, live-обновлением и кнопкой повторной загрузки. Текстовый буфер ограничен 64 КиБ.
- Поток логов использует поддерживаемое динамическое JSON-RPC событие `app.container_log_follow`; при закрытии карточки, смене контейнера или уходе приложения в background подписка освобождается.
- `APPS_READ` разрешает карточки, контейнеры, статистику и их логи; каталоговый fallback иконок дополнительно требует `CATALOG_READ`.
- HTTP остаётся приоритетным режимом в доверенной локальной сети; deprecated REST API и shell/SSH для логов не используются.

## Что подтверждено документацией TrueNAS

- [`app.query` 25.04](https://api.truenas.com/v25.04/api_methods_app.query.html) и [`25.10`](https://api.truenas.com/v25.10/api_methods_app.query.html) требуют `APPS_READ` и возвращают `metadata` как объект, но не фиксируют в публичной схеме имя поля иконки.
- [`catalog.apps` 25.04](https://api.truenas.com/v25.04/api_methods_catalog.apps.html) и [`25.10`](https://api.truenas.com/v25.10/api_methods_catalog.apps.html) явно возвращают допускающий `null` `icon_url` и требуют `CATALOG_READ`.
- [`app.container_log_follow` 25.04](https://api.truenas.com/v25.04/api_events_app.container_log_follow.html) и [`25.10`](https://api.truenas.com/v25.10/api_events_app.container_log_follow.html) — динамическое событие с параметрами `app_name`, `container_id`, `tail_lines`; оно отдаёт `data` и `timestamp` и требует `APPS_READ`.
- [`app.container_ids`](https://api.truenas.com/v25.10/api_methods_app.container_ids.html) возвращает ID, service name, image и state контейнеров и также требует `APPS_READ`.

## Выводы реализации

- Ключи иконки внутри `app.query.metadata` и вложенного `source` обрабатываются best-effort для совместимости, но не считаются гарантированным API-контрактом.
- `catalog.apps.icon_url` — документированный fallback. Каталог запрашивается best-effort: отсутствие `CATALOG_READ`, `null`, custom app без каталога или ошибка загрузки приводят к placeholder, а не к поломанной карточке или dashboard.
- Локальный SVG renderer, хвост в 200 строк и предел текста в 64 КиБ — решения клиента, а не ограничения API TrueNAS.

## Ручная проверка перед публикацией

- Установить v1.5.0 поверх v1.4.0 и убедиться, что адрес, учётные данные, WOL и расписания сохранились.
- Открыть список, где часть приложений имеет картинки, а часть — нет: карточки не должны менять размер или падать во время асинхронной загрузки.
- Для приложения с иконкой дождаться загрузки и проверить в светлой/тёмной теме, что буква не видна под картинкой, по краям или на прозрачных участках.
- Быстро прокрутить список вверх/вниз и несколько раз выполнить переподключение: поздний ответ загрузчика не должен поставить иконку от другого приложения в переиспользованную карточку.
- Проверить `metadata.icon_url`, `metadata.icon`, вложенный `source`, `catalog.apps.icon_url`, растровые и SVG-иконки, HTTP и HTTPS URL; некорректная схема, 404, таймаут, повреждённый SVG и слишком большой ответ должны безопасно оставить placeholder.
- Проверить catalog app с `CATALOG_READ` и без неё. Без роли dashboard должен работать, а отсутствующая иконка — заменяться буквой без общей ошибки подключения.
- Проверить custom app и каталожное приложение с `icon_url: null`: placeholder должен быть стабильным и контрастным, без бесконечной загрузки.
- Открыть подробную карточку: секция «Логи» должна располагаться после всех элементов «Нагрузка» и не перекрывать нижнюю навигацию.
- Для приложения с несколькими контейнерами переключать контейнеры: заголовок и строки должны соответствовать выбранному контейнеру, а старый поток — прекращаться.
- Проверить хвост из 200 строк, новые строки, многострочный вывод, Unicode, очень длинную строку, пустой журнал и `timestamp: null`; после превышения 64 КиБ старый текст должен удаляться без зависания интерфейса.
- Нажать **Обновить логи**: старый поток должен закрыться, а выбранный контейнер — получить свежий хвост без дублирования параллельной подпиской.
- Свернуть приложение, перейти на другую вкладку, закрыть карточку и выполнить полное переподключение: прежняя log-подписка должна закрываться, а после возврата не должно быть дублей.
- Остановить/запустить/переразвернуть приложение при открытой карточке: устаревший `container_id` должен обрабатываться без падения, после обновления должен появиться актуальный список.
- С пользователем без `APPS_READ` проверить понятное отсутствие логов без влияния на пинг, WOL, пулы и доступные системные метрики.
- Повторно проверить RU/EN, светлую/тёмную темы, увеличенный системный шрифт, портретный режим и основные Start/Stop/Deploy/Update операции.

Поддерживается Android 8.0 (API 26) и новее. Целевая версия сервера — TrueNAS SCALE 25.04 и новее.
