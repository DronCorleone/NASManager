# Настройка TrueNAS SCALE 25.10 для NAS Manager

NAS Manager 1.1.0 подключается только к `wss://<сервер>/api/current`. API key является эквивалентом пароля, поэтому TrueNAS отзывает его при любой попытке аутентификации через HTTP/WS.

## 1. Настройте имя и HTTPS-сертификат

Рекомендуемый вариант — отдельное DNS-имя, например `truenas.example.com`, которое внутри домашней сети разрешается в локальный IP сервера.

### Вариант A: публично доверенный сертификат

1. В **Credentials → Certificates → ACME DNS-Authenticators** добавьте DNS-провайдера.
2. Создайте CSR, указав имя сервера в Common Name и Subject Alternative Names.
3. Для CSR создайте ACME-сертификат.
4. Откройте **System → General Settings → GUI → Settings**.
5. Выберите сертификат в **GUI SSL Certificate**, сохраните настройки и подтвердите перезапуск Web UI.

DNS-01 validation не требует публиковать TrueNAS в интернет. Не пробрасывайте порт административного интерфейса наружу.

### Вариант B: собственный локальный центр сертификации

1. Выпустите серверный сертификат с SAN, совпадающим с DNS-именем TrueNAS.
2. Импортируйте сертификат и закрытый ключ в **Credentials → Certificates**.
3. Назначьте его как **GUI SSL Certificate**.
4. Установите корневой сертификат локального CA на Android через системные настройки безопасности.

Приложение доверяет пользовательским CA, но продолжает проверять имя сервера. Самоподписанный сертификат без доверенного CA использовать не следует.

Перед созданием ключа откройте на телефоне `https://<имя-сервера>` и убедитесь, что Android не показывает предупреждение о сертификате.

## 2. Создайте новый API key

Старый ключ с причиной отзыва `Attempt to use over an insecure transport` восстановить нельзя.

1. Откройте меню пользователя TrueNAS → **My API Keys**. Альтернативный путь: **Credentials → Users → пользователь → View API Keys**.
2. У старого ключа выберите **Edit → Reset** либо удалите его и создайте новый.
3. Скопируйте новую строку ключа сразу: TrueNAS показывает её только один раз.
4. Запомните точное имя пользователя-владельца ключа — оно требуется `auth.login_ex`.

Для полного функционала владельцу ключа нужны права чтения System/Pool/Reporting/Apps/Alerts, `APPS_WRITE` для управления приложениями и `FULL_ADMIN` для выключения сервера. Если удалённое выключение не нужно, можно использовать менее привилегированного пользователя.

## 3. Заполните настройки NAS Manager

- **Адрес TrueNAS:** `https://truenas.example.com` — только origin, без `/ui`, `/api` и завершающих путей.
- **Пользователь TrueNAS:** точное имя владельца ключа.
- **Ключ API:** новый ключ, созданный после настройки HTTPS.
- **MAC-адрес:** MAC интерфейса, для которого включён Wake-on-LAN.
- **Broadcast:** например `192.168.31.255` для сети `192.168.31.0/24`.

Нажмите **Проверить подключение**. При ошибке приложение покажет полный ответ TrueNAS или TLS, который можно скопировать.

## 4. Расшифровка типовых ошибок

- **TrueNAS API keys require HTTPS** — в URL указан `http://`.
- **TLS certificate validation failed** — сертификат не доверен Android либо его SAN не совпадает с именем в URL.
- **AUTH_ERR** — неверное имя пользователя, ключ отозван либо ключ принадлежит другому пользователю.
- **EXPIRED** — истёк срок ключа.
- **Not authorized / permission denied** — владельцу ключа не хватает роли для конкретного раздела или действия.
- **RESTAPIUsage** — к серверу обращается старый клиент через `/api/v2.0`. NAS Manager 1.1.0 REST не использует. Алерт отражает обращения за последние 24 часа и может исчезнуть не сразу.
